# Navibrain Development TODO & TDD Workflow

This file tracks the development process for the first version of Navibrain, adhering to the required Test-Driven Development (TDD) workflow and specifying points for user feedback.

## Workflow Rules
1. **Test-Driven Development (TDD):** For every new feature or component, write the tests FIRST. Ensure they fail. Then implement the feature to make them pass.
2. **Refactoring:** After tests pass, refactor the code for maximum readability. Run tests again to ensure nothing broke.
3. **Checkpoints:** At specific milestones marked with `[FEEDBACK POINT]`, the AI assistant will stop and ask the user for feedback before proceeding.
4. **Git Operations:** Always run `git status` before `git commit`.
5. **Alembic:** All Alembic autogenerated migrations must be reviewed by the user before running, stripping out anything unrelated to the current change.
